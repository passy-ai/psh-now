OpenCode + psh.now

One skill installs the command that posts a request and waits for the decision.

OpenCode loads the skill from ~/.config/opencode/skills. From there the agent sends one HTTP request per decision and waits on the reply. psh.now is MIT licensed, so the server side is yours to read, run and host.

Install the skill

Either command works. The first pulls the packaged skill through npm; the second is a shell installer that needs neither npm nor git.

npx skills add passy-ai/psh-now-skill -g -y
curl -fsSL https://psh.now/install.sh | sh

The skill lands in ~/.config/opencode/skills/psh-now, where OpenCode reads it. The installer writes the shared skills directory as well, so other agents on the same machine find it too.

Connect a channel

Open the dashboard, copy the prompt from a channel card and give it to OpenCode. The link carries the channel. The key it comes back with is ask-only: it can post requests there, not approve them. A decision needs a person, or a key scoped to that channel for the purpose. 

I'd like you to use psh.now and join this channel: https://psh.now/c/<channel>

What a request carries

Once the skill is installed, the agent's side of the contract is one command:

psh ask "Deploy the new build?" "This pushes to production."

The call stays open while the agent waits. It exits 0 on approval and non-zero otherwise. When the request expires or is cancelled the exit is non-zero, because an expiry is not an approval.

Ask or gate

A skill is an ask: OpenCode can skip it. Where your setup exposes a permission hook, wire psh hook and the same request becomes a gate the model cannot get past without an answer. Claude Code is the reference: see its hook.

Check it works

psh status

Expect the host, auth ✓, the plan and the request count. psh doctor prints the skill path, the keys, the workspace and any stale record.
