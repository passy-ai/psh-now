Cline + psh.now

A skill Cline can call before a step it is about to take.

Cline reads the shared skills directory. Install the skill and a step it is about to take (a delete, a force push, a migration) can become one HTTP request that stays open until a person answers it.

Install it

Two commands, either one. The first installs the packaged skill. The second pipes the installer.

npx skills add passy-ai/psh-now-skill -g -y
curl -fsSL https://psh.now/install.sh | sh

The skill lands in ~/.agents/skills/psh-now, the shared directory the other harnesses read as well.

Connect a channel

Open the dashboard, copy the prompt from a channel card, and paste it into Cline. The link carries the channel, so nothing new is created, and the key Cline receives is ask-only: it can request an approval, never grant one. 

I'd like you to use psh.now and join this channel: https://psh.now/c/<channel>

What it asks with

The agent's side of the contract is one command:

psh ask "Deploy the new build?" "This pushes to production."

The call stays open until someone answers, then prints the decision. Read it before running the step. A timeout or an error is not an approval.

Skill or hook

A skill is an ask: the model can skip it. Where the setup exposes hooks, wire psh hook instead, and the same request becomes a gate the model cannot skip. Claude Code is the reference: see its hook.

Check the install

psh status

It prints the host, auth ✓, the plan and the request count. psh doctor prints the skill path, the keys, the workspace and any stale record.
