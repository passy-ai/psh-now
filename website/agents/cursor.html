Cursor + psh.now

Every step Cursor is about to take can become one request, and you answer it away from the terminal.

Cursor reads skills from ~/.cursor/skills. The agent already has a terminal, which is all psh.now needs: it posts the step it is about to take, the call stays open, and a person answers from a phone, a browser or the macOS notch.

Install the skill

Two commands, either one. The first installs the packaged skill; the second needs no npm and no git.

npx skills add passy-ai/psh-now-skill -g -y
curl -fsSL https://psh.now/install.sh | sh

It lands in ~/.cursor/skills/psh-now, where Cursor looks for skills. The shared skills directory is written as well, so the same install is picked up by the other harnesses.

Connect a channel

Open the dashboard, copy the prompt from a channel card and give it to Cursor. The link carries the channel, so the key Cursor receives is scoped to that channel and is ask-only. 

I'd like you to use psh.now and join this channel: https://psh.now/c/<channel>

What the agent sends

Once installed, the agent's side is one command:

psh ask "Deploy the new build?" "This pushes to production."

It blocks until a person answers, then prints the decision. A timeout, an expiry or an error means the step did not happen. The default window is 90 seconds, 15 minutes at most.

Ask or gate

Cursor runs the skill, and a skill is an ask: the model can skip it. Where your setup exposes a permission hook, wire psh hook instead and the same request gates the step, because it reads JSON on stdin and waits for a decision. Claude Code is the worked example: see its hook.

Check it works

psh status

Expect the host, auth ✓, the plan and the request count. psh doctor checks further: the skill path, the keys, the workspace and any stale record.
