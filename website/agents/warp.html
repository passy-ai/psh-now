Warp + psh.now

A step in the terminal becomes a request you answer from a phone, a browser or the notch.

Warp reads the shared skills directory, so the skill is installed once. From then on the agent posts a request over HTTP before a step and its call stays open while you decide.

Install the skill

Either command works. The first installs the packaged skill; the second pipes the installer to a shell and needs no npm and no git.

npx skills add passy-ai/psh-now-skill -g -y
curl -fsSL https://psh.now/install.sh | sh

It lands in ~/.agents/skills/psh-now, the shared directory that agents read, and no further setup is needed.

Connect a channel

Open the dashboard, copy the prompt from a channel card, and give it to Warp. The link names the channel, and the key the agent receives is ask-only: it can post a request, never decide one. 

I'd like you to use psh.now and join this channel: https://psh.now/c/<channel>

The command the agent runs

The agent's side of the exchange is one command:

psh ask "Deploy the new build?" "This pushes to production."

It blocks until you answer, then prints the decision. The window is 90 seconds by default and 15 minutes at most. When it closes the call returns expired, which is not an approval.

Ask or gate

Warp runs the skill, and a skill is an ask: the model can skip it. If your setup exposes hooks, wire psh hook and the request comes from the hook instead, so the step cannot proceed without an answer. psh hook reads JSON on stdin, and the Claude Code hook is the reference: see its hook.

Check the install

psh status

It prints the host, auth ✓, the plan and the request count. psh doctor reports the skill path, the keys, the workspace and any stale record.
