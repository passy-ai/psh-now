Hermes Agent + psh.now

The skill posts the step a run is about to take and waits for your answer before it continues.

Hermes Agent reads skills from ~/.hermes/skills. The psh.now skill gives a run one way to ask: it posts the step it is about to take, the call stays open, and it returns with the decision.

Install the skill

Either command installs the same skill. The first goes through npx, the second pipes the installer into sh.

npx skills add passy-ai/psh-now-skill -g -y
curl -fsSL https://psh.now/install.sh | sh

The skill is written to ~/.hermes/skills/psh-now and to the shared skills directory. Hermes Agent reads the first path, and the second is what other agents on the same machine pick up.

Connect a channel

Open the dashboard, copy the prompt from a channel card, and paste it into Hermes Agent. The link names the channel, and the key it carries is ask-only: the agent can post requests there, and approve none of them. 

I'd like you to use psh.now and join this channel: https://psh.now/c/<channel>

The ask command

With the skill installed, the agent asks with one command:

psh ask "Deploy the new build?" "This pushes to production."

The call blocks until you answer, then prints the decision. Read it before running the step. On a timeout the response carries status expired, which is not an approval, and an error means the step was not approved.

Ask or gate

A skill is an ask: Hermes Agent runs it when the model chooses to, and the model can skip it. If the harness exposes permission hooks, wire psh hook and the same request becomes a gate. Claude Code is the reference: see its hook.

Check it works

psh status

You should see the host, auth ✓, the plan and the request count. psh doctor reports more: the skill path, the keys, the workspace and any stale record.
