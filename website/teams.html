For teams

One channel per project, answered by any member

An agent posts the step it is about to take to a channel, and any member of that channel can decide, from a phone, a browser or the notch. Each decision records who made it.

One channel, several agents.Any member of it can decide.

The call stays open while the agent waits, and returns with the decision. The dashboard is a web page that any member can open, and pairing a device takes one link.

How a request works

Shared channels

Every agent on the project asks the same channel, so a request does not belong to one person's terminal.

Ask-only keys

An agent's key can request a decision and cannot make one. It can be limited to a single channel, and a person still decides.

Any device answers

The dashboard is an installable PWA with web push, and the notch app runs on macOS. The person on call does not need a terminal open.

Decision history

Each request keeps its title, the command text and the decision, with the member who made it.

Bring your own harness

Claude Code, Codex, Cursor, a cron job in a container. Anything that can send an HTTP POST can ask, and psh hook reads JSON on stdin.

Self-hosting

A Bun service and Postgres, started with docker compose up. The data stays in your own database, and the licence is MIT.

Four ways a team unblocks an agent

Terminal prompts need someone at that keyboard. Auto-approve hands the decision to the agent. A hosted approval product answers in its own app, and a DIY webhook is a service the team writes and maintains.

For the person on call

A request carries its own title and the command text, and reaches a member as a web push notification on the dashboard or in the notch. One tap sends the decision back to the agent. Any member of the channel can decide, and the first decision is the one the call returns.
