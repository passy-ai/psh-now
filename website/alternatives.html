Open source approvals you can run yourself

An agent that needs a person has three common options: run without asking, wait on a prompt in the terminal, or post to a hosted service. psh.now is a fourth. The agent posts one HTTP request and the connection stays open while it waits; a person approves, denies or answers it from a phone, a browser or the notch, and the call returns with that decision. The server is MIT licensed, so it is yours to run.

A page for each comparable product

Each page below covers one product, what it does, and the case where it is the better choice.

Pushary

Pushary is a hosted approval service for agents. Pick it if you want one vendor running the queue for you. Pick psh.now if you want to read the source and keep the server in your own infrastructure.

AgentPeek

AgentPeek is a Mac app that puts agent permissions in the notch. Pick it if the person answering is sitting at that Mac. Pick psh.now if that person is on a phone.

If you were about to use auto-approve

Auto-approve runs the command without asking: --yolo, --dangerously-skip-permissions, an agent with no permission gate. Nothing checks a recursive delete or a force push before it runs. psh.now keeps the question and sends it to a person, who approves, denies or answers it from a phone, a browser or the notch; the agent's call stays open until that decision comes back.

Risky steps still ask

A recursive force delete, a force push, sudo, DROP or TRUNCATE, a kubectl delete of a namespace: these stop and wait for a person. The risk label is read from the command text and names the pattern it matched.

The answer does not need a keyboard

One tap on a phone clears the request while the agent waits. The window is 90 seconds by default and 15 minutes at most; when it closes, the request expires and that is not an approval.

If you were about to pay for a hosted approval service

A hosted approval service runs the queue, the app and the keys for you, and many teams find that worth paying for. The request and its decision then live on someone else's server, under their retention policy. The psh.now server is MIT licensed, so you can read it, run it and fork it.

Read every rule

The rules that decide which commands need a person are in the repository, in code you can read and change.

Requests stay in your database

Self hosting is a Bun service and Postgres. Requests, keys and decisions stay in your own database, and you decide how long they are kept.

If you were about to build it yourself

A webhook, a Slack bot and a database covers the delivery. It still leaves the deciding, the keys, the install and the phone to build. psh.now is that shape already built: one request in, one decision out, with the CLI, a Claude Code hook and the MCP endpoint included.

One call, one decision

POST a title and a message to https://psh.now/api/v1/approvals and hold the connection open. The response carries the decision: approved, denied, or a written answer.

Fork it if the rule is wrong

The source is on GitHub under the MIT licence, so a rule you disagree with is yours to change.

Why the source matters

An approval server sits between an agent and the commands it wants to run. Whoever operates it holds the requests, the keys and the decisions. On the hosted instance they live on this server; self-hosted they stay in your database.

MIT licensed

The server and the skill are MIT licensed on GitHub, risk rules included.

Self-hosted if you want it

A Bun service and Postgres. docker compose up starts both, and the data stays in your own database.

No lock-in

The protocol is one HTTP request to one endpoint. A self-hosted install keeps requests, keys and decisions in your own Postgres database.

Send one request

Free to start, with no account and no card. An approval costs two requests, one in and one out, and a request that expires or is cancelled costs nothing.
