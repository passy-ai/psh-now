Run psh.now yourself

psh.now is MIT licensed and runs as one Bun process in front of Postgres. Two containers, three required environment variables and a domain that resolves to the host. docker compose up starts both, and requests, agent keys and history stay in your own database. The sections below cover each variable, mail, TLS, the first account, upgrades and the proxy timeouts that decide whether an approval can wait.

Quick start

git clone https://github.com/passy-ai/psh-now && cd psh-now
cp .env.example .env

# the two that compose refuses to start without
PUBLIC_BASE_URL=https://psh.example.com
PSH_SECRET=$(openssl rand -base64 48)

# sign-in needs one of these
MAIL_FROM="psh.now <no-reply@example.com>"
SMTP_URL=smtps://user:password@smtp.example.com:465

docker compose up -d --build

Migrations run inside the container on start, retried up to ten times, so there is no separate migrate step to forget. The app listens on http://localhost:3000. Put TLS in front of it before you pair a device: pairing links are built from PUBLIC_BASE_URL, so they carry whatever scheme and host it holds.

Environment

Three variables are required. Compose refuses to start without the first two; the rest have defaults that work. 

PUBLIC_BASE_URL   required   the URL people and agents will use, no trailing slash
PSH_SECRET        required   encrypts stored agent keys; 32+ random bytes
DATABASE_URL      required   compose builds it from POSTGRES_* for you

MAIL_FROM         mail       the From line, e.g. psh.now <no-reply@example.com>
SMTP_URL          mail       smtps://user:pass@smtp.host:465
RESEND_API_KEY    mail       alternative to SMTP_URL

PORT              3000       app port inside the container
DEFAULT_TIMEOUT_MS  90000    how long an ask waits for a human
PAIRING_TTL_MS    600000     how long a pairing link lives
PSH_FREE_REQUESTS 20         requests granted before a confirmed account
PSH_CLAIMED_REQUESTS 100     requests granted to a confirmed account

Rotating PSH_SECRET is not supported in place. It encrypts recoverable agent keys at rest, so a new value leaves every stored key undecryptable. Back it up with the database, in the same archive.

Mail

Email is the only sign-in. Set MAIL_FROM and one transport:

  • SMTP (SMTP_URL) works with your own Postfix, SES, Postmark, Fastmail, or a Gmail app password. Use smtps:// for implicit TLS on 465, smtp:// on 587 with STARTTLS.
  • Resend (RESEND_API_KEY) if you would rather not run a mail server. It needs a verified sending domain.

With neither set the server still boots and logs mail: not configured. In development the code is printed to the console and returned in the API response, so local sign-in needs no transport at all. In production, sign-in returns an error instead of reporting a send that did not happen.

TLS

Two shapes are supported. Caddy is one file:

# Caddyfile
psh.example.com {
  reverse_proxy app:3000
}

Or hand certificates to Bun directly with TLS_CERT_FILE and TLS_KEY_FILE and skip the proxy. With nginx or Cloudflare in front, read Limits and proxies before you test an approval.

First account

  1. Open https://psh.example.com/app.
  2. Enter your email, then the six digit code that arrives in that mailbox.
  3. Open /devices and pair a phone or the Notch app. The pairing link is built from PUBLIC_BASE_URL, so a wrong value here is the most common first-run failure.

There is no seeded admin and no default password. The first person to claim a workspace owns it, so claim the instance before a public hostname points at it.

Connecting agents

An agent needs a key and one POST, no plugin. The installer leaves the skill, a psh command on PATH and this project's keys in place: 

npx skills add passy-ai/psh-now-skill -g -y
curl -fsSL https://psh.example.com/install.sh | sh

Or skip the install and point the agent at the instance: give it the channel key from /channels and the prompt at /docs#sandbox. The psh command is a shell script over curl, so it runs anywhere an agent can run a command.

Upgrades and backups

git pull
docker compose up -d --build          # migrations run on start

# backup: database and the secret together, or neither is useful
docker compose exec db pg_dump -U psh.now psh.now > psh-$(date +%F).sql
printf '%s\n' "$PSH_SECRET" > psh-secret.txt

Restoring takes the same two files: a fresh volume, psql < dump, and the original PSH_SECRET. A dump without the secret restores rows whose encrypted values cannot be read.

Limits and proxies

An ask holds the connection open until a person answers, so its length is capped by whatever sits in front of the instance. Keep DEFAULT_TIMEOUT_MS below that limit:

  • Cloudflare: 100s, and a longer wait becomes a 524.
  • nginx proxy_read_timeout: 60s by default.
  • Caddy: no limit.

The cap is 15 minutes. Compose passes DEFAULT_TIMEOUT_MS from your .env, and the server falls back to 90s when the variable is unset, so set it under the shortest limit in front of you. Timeouts that land on the same second every time come from the proxy closing the connection before the answer arrives.

What is not included

  • Apple push to a native iOS app. That needs an Apple push key and a signed app, which the hosted instance carries. Web push is part of this instance: the dashboard is an installable PWA and the server generates VAPID keys on first use, so alerts reach a closed tab or a phone. On iOS the site has to be added to the Home Screen before push arrives.
  • A signed Notch build. The app builds from tools/psh-notch with swiftc on macOS 13 or later; you sign it yourself.
  • Billing. Dodo Payments is optional. Unset, the checkout reports off and the packs are not offered.
  • Managed anything. No uptime monitoring, no off-site backup, no support rotation. It is your instance.

Troubleshooting

  • Compose exits immediately. It refuses to start without PUBLIC_BASE_URL and PSH_SECRET; the error names the missing one.
  • Sign-in says the code could not be sent. No mail transport is configured. Set SMTP_URL or RESEND_API_KEY, plus MAIL_FROM, and restart.
  • Pairing link points at localhost. PUBLIC_BASE_URL is still the default. Fix it and restart.
  • 403 on sign-in from another origin. The app trusts PUBLIC_BASE_URL plus localhost in development. Open the host you configured rather than its IP.
  • Every query is slow. Postgres over a tunnel or a distant managed database adds a round trip per query. Run the database next to the app.

The repository copy at docs/self-hosting.md records what was verified on a clean machine, the two limits a hoster cannot guess, and how the hosted instance deploys.
