Documentation

How to install the skill, connect an agent, answer requests, and call the API directly.

Overview

An agent sends a request with a title and a message, and the call stays open. You approve, deny or answer it from the dashboard, your phone or the notch, and the call returns the decision.

  • One dashboard for every agent, on any device.
  • Many agents can share one channel.
  • Many people can approve one channel.

Any agent with shell or HTTP access can use it: one POST, no SDK. An MCP client can use /mcp instead, and nothing else depends on that endpoint.

Prompt templates

Three prompts cover what you normally paste into an agent. All three are on this page, and the install report prints the connect and sandbox ones with your channel and key already filled in.

  • Install: the one-line setup prompt.
  • Connect an agent: the link a channel card copies.
  • Sandbox / no browser: the same job with a channel key instead of a link.

Install

Give the agent this prompt. It installs the skill and sends a test request:

I'd like you to set up psh.now: Install as a skill with npx skills add passy-ai/psh-now-skill -g -y

If not, do this instead: curl -fsSL https://psh.now/install.sh

After installing, send me a test request.

Without npm, git or GitHub access, run the installer directly; it mints the keys as well. It puts the skill in every agent folder it finds, writes a psh command into the first writable directory on PATH, and records the machine account in ~/.psh/keys.json. A sandbox that refuses those writes keeps the skill in the project and prints psh_machine_wide=incomplete:

curl -fsSL https://psh.now/install.sh | sh

Joining a channel, with the connect prompt below, gives the folder its own ./.psh/bin/psh and ./.psh/keys.json. The install prints one screen with the skill, the host, the keys and the next command, and ./.psh/bin/psh doctor checks the whole path. Until the machine-wide copy has run, the install is project-local and says so.

The agent can send a test request whenever you want to watch the round trip.

Connect an agent

Each dashboard channel shows a ready-to-paste prompt above its tabs. For an agent that already has the skill: 

I'd like you to use psh.now and join this channel: https://psh.now/c/<channel>

The link carries an ask-only key, which can request approvals and cannot approve them. It is reusable, so several agents can join one channel.

The key never goes into a file you commit. It lives in ~/.psh/keys.json (mode 0600) or in PSH_API_KEY in the agent's environment, and the block in agents.md only points at it.

Sandbox / no browser

A container, a chat agent or a laptop that has never seen psh.now joins through the channel link. This prompt installs and joins in one go, so the agent joins your channel instead of minting a second account. 

I'd like you to set up psh.now: Install as a skill with npx skills add passy-ai/psh-now-skill -g -y
and join https://psh.now/c/<channel>

If not, do this instead: curl -fsSL https://psh.now/install.sh

The link decides the account and the channel, so nothing new is minted and the key stays ask-only. It is the channel's reusable /c/<channel> URL: the share button on the card shows it, a connected folder keeps it in .psh/keys.json, and psh status prints it. Joining with it already set keeps the work on your account.

This is the block an install prints in its report, under Copy this prompt into any agent.

Approving requests

Pending requests sit at the top of the dashboard, one card each: the title, the message, and three buttons, Deny, Answer and Approve. Answer takes your own words when the question needs more than a yes or a no. Approve or Deny settles the rest, and the card goes.

An agent proceeds only on {"approved":true}. A timeout or an error means do not act.

Channels

A channel is one project's container and a card on the dashboard. Everything it needs sits on that card:

  • Copy prompt for agent: the ready-to-paste prompt, with the channel's link inside it.
  • Who's in this channel: the people and agents on it, each agent's key, and a reusable invite link.
  • More actions: Rename, Export history (CSV), Archive.

Create one with ＋ New channel. Requests that never named a channel land in Default.

Archive takes a card off the dashboard and keeps everything: the channel, its agent keys, its people and its requests. Archived channels live under Archived channels in the account menu, which puts one back on the dashboard. Deleting from that page is the permanent one: it removes the channel and the requests in it, so archive first and delete only when the history is not needed.

Export history (CSV) downloads every decided request in the channel within your plan's history window: requested time, request, the full details, status, answer, decision, agent, who decided and when. The details are not cropped the way the dashboard crops a row, so a message with commas or line breaks reads as one cell and one row.

Account & billing

Your account key is your login: it signs you in at /app?key=… and it is the identity an anonymous workspace uses. Claim account with an email to keep it, sign in from any device, raise the allowance from 20 requests to 100, and extend history from 7 days to 30.

Out of requests? Top up from the dashboard: 100 for €1, then 1,000 for €9, 10,000 for €50, 100,000 for €450. VAT, with a company-details option for the invoice.

API

The core call, which returns the decision:

curl -s -X POST https://psh.now \
  -H "x-psh-key: psh_agent_…" \
  -H "Content-Type: application/json" \
  -d '{"title":"Reinstall dependencies","message":"rm -rf node_modules && npm install --force"}'

Async (returns immediately, then poll):

curl -s -X POST https://psh.now \
  -H "x-psh-key: psh_agent_…" -H "Content-Type: application/json" \
  -d '{"title":"Deploy","message":"Deploy the new build?","wait":false}'
# -> { "status":"pending", "approved":false, "pollUrl":"…/api/v1/approvals/…" }
curl -s "$POLL_URL?wait=30" -H "x-psh-key: psh_agent_…"

API reference (Scalar): /openapi, full OpenAPI: /openapi.json, agent context: /llms-full.txt

MCP

The HTTP call above is the contract. For clients that cannot install a skill, the same request is also a single MCP tool at /mcp (streamable HTTP, plain JSON responses, no OAuth). One tool, psh_ask, with {title?, message, timeoutSec?}; it blocks and returns {"approved":bool,"status":"approved|denied|answered|expired","answer":string|null}.

claude mcp add --transport http psh https://psh.now/mcp \
    --header "x-psh-key: psh_agent_…"
{ "mcpServers": { "psh": {
      "url": "https://psh.now/mcp",
      "headers": { "x-psh-key": "psh_agent_…" } } } }

Descriptor: /.well-known/mcp.json. Published in the official MCP registry as io.github.passy-ai/psh-now, and it answers protocol 2025-06-18, 2025-03-26 and 2024-11-05. Only approved: true means yes; an answer is the person's own words, which is not permission. MCP is cooperative, like the skill: it cannot stop an agent that ignores it. The harness hook is the gate.

Limits

  • Anonymous - 20 requests total, 7-day history.
  • Claimed (email) - 100 requests total, 30-day history.
  • Prepaid: packs on top of the allowance, 90-day history.

One approval costs 2 requests (inbound + outbound).
