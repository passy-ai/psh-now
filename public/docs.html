Documentation

Setup, the approve/deny contract, the prompt templates and the HTTP API, everything needed to connect an agent to psh.now.

Overview

psh.now lets your agents ask you for approval instead of stalling in the terminal. An agent sends a short title and message; you tap Approve or Deny from one page; the agent gets a single boolean.

  • One page you check from your phone.
  • Many agents can share one channel.
  • Many people can approve one channel.

It's harness-agnostic: any agent with shell or HTTP access can use it. One HTTP call is the whole contract, with no SDK to install. If a client speaks MCP instead there is an endpoint at /mcp, and nothing depends on it.

Prompt templates

Three prompts cover almost everything you paste into an agent. All three are on this page, ready to copy - and an install's report prints the connect and sandbox ones already filled in with your channel and key.

  • Install - the one-line setup prompt.
  • Connect an agent - the link prompt a channel card copies.
  • Sandbox / no browser - the same job with a channel key instead of a link.

Install

Give your agent this one prompt. It installs psh.now and asks for a test request:

I'd like you to set up psh.now: Install as a skill with npx skills add passy-ai/psh-now-skill -g -y

If not, do this instead: curl -fsSL https://psh.now/install.sh

After installing, send me a test request.

No npm, no git, or no GitHub access? Run the installer directly - it mints your keys too. It installs the skill in every agent folder it finds, writes a psh command into the first writable directory on your PATH, and records the machine's account in ~/.psh/keys.json. A sandbox that refuses those writes leaves the skill in this folder and says so, psh_machine_wide=incomplete:

curl -fsSL https://psh.now/install.sh | sh

Joining a channel - the connect prompt below - is what gives the folder its own ./.psh/bin/psh and ./.psh/keys.json: one screen naming the skill, the host, the keys and the next command, and ./.psh/bin/psh doctor checks it end to end. Until the machine-wide copy has run the install is project-local, and the agent says so rather than calling it finished. (Also written "psh now" or psh-now.)

After installing, you can have the agent send one test question through psh.now whenever you want to see it work end to end.

Connect an agent

Every channel shows a ready-to-paste prompt. Open the dashboard → a channel → copy the prompt above the tabs. An agent that is already installed gets: 

I'd like you to use psh.now and join this channel: https://psh.now/c/<channel>

The link gives the agent an ask-only key - it can request approvals, never approve - and it is reusable, so several agents can connect through the same channel.

The key never goes into a file you commit. It lives in ~/.psh/keys.json (mode 0600) or in PSH_API_KEY in the agent's environment; the block you paste into agents.md only refers to it.

Sandbox / no browser

A container, a chat agent and a laptop all join through the channel's link, and none of them is set up yet: this is the prompt for a new sandbox. It installs and joins in the same prompt, so the agent joins the channel instead of minting a second account, and the fallback line stays a plain install. 

I'd like you to set up psh.now: Install as a skill with npx skills add passy-ai/psh-now-skill -g -y
and join https://psh.now/c/<channel>

If not, do this instead: curl -fsSL https://psh.now/install.sh

The link decides the account and the channel, so nothing new is minted and the agent stays ask-only. It is the channel's reusable /c/<channel> URL: the share button on the card shows it, and an already-connected folder has it in .psh/keys.json or can print it with psh status. Joining with it already set is what keeps the work on your account.

This is the block an install prints in its report - the only prompt there, under Copy this prompt into any agent - a chat, or a sandbox.

Approving requests

Waiting requests appear at the top of the dashboard, one card each: the title, the message, and three buttons - Deny, Answer and Approve. Answer replies in your own words when the question needs more than a yes or no; otherwise Approve or Deny settles it and the card disappears.

An agent proceeds only on {"approved":true}. A timeout or an error means do not act.

Channels

A channel is one project's bucket (e.g. my-project), and it is a card on the dashboard. Everything it needs lives on that card:

  • Copy prompt for agent - the ready-to-paste prompt, with the channel's link inside it.
  • Who's in this channel - the people and agents on it, each agent's key, and a reusable invite link.
  • More actions - Rename, Export history (CSV), Archive, Delete.

Create one with ＋ New channel. Requests that never named a channel land in Default.

Account & billing

Your account key is your login - it signs you in at /app?key=… and is your identity while anonymous. Claim account with an email to keep it, sign in from any device, and lift the allowance from 20 requests to 100.

Out of requests? Top up from the dashboard: 100 for €1, then 1,000 for €9, 10,000 for €50, 100,000 for €450. VAT, with a company-details option for the invoice.

API

The core call - one boolean back:

curl -s -X POST https://psh.now \
  -H "x-psh-key: psh_agent_…" \
  -H "Content-Type: application/json" \
  -d '{"title":"Reinstall dependencies","message":"rm -rf node_modules && npm install --force"}'

Async (returns immediately, then poll):

curl -s -X POST https://psh.now \
  -H "x-psh-key: psh_agent_…" -H "Content-Type: application/json" \
  -d '{"title":"Deploy","message":"Deploy the new build?","wait":false}'
# -> { "status":"pending", "approved":false, "pollUrl":"…/api/v1/approvals/…" }
curl -s "$POLL_URL?wait=30" -H "x-psh-key: psh_agent_…"

API reference (Scalar): /openapi, full OpenAPI: /openapi.json, agent context: /llms-full.txt

MCP

The HTTP call above is the contract. For clients that cannot install a skill, the same request is also a single MCP tool at /mcp (streamable HTTP, plain JSON responses, no OAuth). One tool, psh_ask, with {title?, message, timeoutSec?}; it blocks and returns {"approved":bool,"status":"approved|denied|answered|expired","answer":string|null}.

claude mcp add --transport http psh https://psh.now/mcp \
    --header "x-psh-key: psh_agent_…"
{ "mcpServers": { "psh": {
      "url": "https://psh.now/mcp",
      "headers": { "x-psh-key": "psh_agent_…" } } } }

Descriptor: /.well-known/mcp.json. Published in the official MCP registry as io.github.passy-ai/psh-now, and it answers protocol 2025-06-18, 2025-03-26 and 2024-11-05. Only approved: true means yes; an answer is the person's own words, not permission. MCP is cooperative like the skill - it cannot stop an agent that ignores it. The gate is the harness hook.

Limits

  • Anonymous - 20 requests total, 7-day history.
  • Claimed (email) - 100 requests total, 30-day history.
  • Prepaid - packs on top of the allowance, 30-day history.

One approval costs 2 requests (inbound + outbound).
